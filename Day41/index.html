01 Values, Variables & Types Foundation

Every JS program is a story about values moving through variables. This module builds the vocabulary — let, const, primitive types, and how JavaScript quietly converts between them — that every later module depends on.

Explanation

Variables are named boxes that hold a reference to a value. Declare them with let (reassignable) or const (cannot be reassigned — though the value it points to can still be mutated if it's an object). Avoid var: it's function-scoped and hoists in confusing ways, a leftover from JS's earliest days.

JavaScript has seven primitive types — string, number, boolean, undefined, null, symbol, bigint — plus object (which covers objects, arrays, and functions). Primitives are compared and copied by value; objects are compared and copied by reference. 

// declaring and typing values
const price = 499;          // number, cannot be reassigned
let currency = "INR";       // string, can change later
let inStock = true;         // boolean
let discount;                // undefined — declared, no value yet

console.log(typeof price);   // "number"
console.log(typeof currency);// "string"
Analogy

const is like writing a name on a parking spot with permanent marker — the spot itself is fixed, but if a car (object) is parked there, you can still repaint the car. let is a spot with a whiteboard label you can erase and rewrite.

Comparison

let

  • Block-scoped
  • Can be reassigned
  • Not hoisted usably (temporal dead zone)

const

  • Block-scoped
  • Cannot be reassigned
  • Object contents can still change

02 Functions & Scope Building Blocks

Functions are how you package behavior. This module covers declarations vs expressions vs arrow functions, parameters, return values, and how scope decides what a piece of code can "see."

Explanation

A function declaration is hoisted (usable before its definition in the file); a function expression or arrow function assigned to a variable is not. Arrow functions also don't bind their own this — they inherit it from the surrounding scope, which makes them ideal for callbacks.

Scope is the region of code where a variable is accessible. JS uses lexical scoping: a function's access to variables is determined by where it's written, not where it's called. Each { } block creates a new scope for let/const. 

// three ways to write "the same" function
function greet(name) { return `Hello, ${name}`; }         // declaration — hoisted
const greet2 = function(name) { return `Hi, ${name}`; }; // expression
const greet3 = (name) => `Hey, ${name}`;                    // arrow

function outer() {
  let secret = "visible only inside outer";
  function inner() { console.log(secret); } // inner can "see" secret
  inner();
}
outer();
Analogy

Scope is like rooms in a house with one-way glass. A room can see everything in the rooms that contain it (its parents), but parent rooms can't see inside child rooms. Variables declared in an inner room simply don't exist once you step outside it.

Comparison

Regular function

  • Own this binding
  • Hoisted (if declaration)
  • Has arguments object

Arrow function

  • Inherits this from enclosing scope
  • Not hoisted the same way
  • No own arguments object

03 Objects & Arrays Practical Application

Real programs are built from structured data. This module covers object literals, destructuring, array methods (map, filter, reduce), and the spread operator — the everyday toolkit of working JS.

Explanation

Objects are key-value collections — the closest thing JS has to a record or struct. Arrays are ordered lists with powerful built-in iteration methods. map() transforms each element into a new array; filter() keeps elements matching a condition; reduce() folds the array into a single value.

Destructuring unpacks values from objects/arrays into variables in one line. The spread operator (...) expands an iterable — useful for copying arrays/objects without mutating the original. 

// object + destructuring
const student = { name: "Aarav", marks: [88, 92, 79] };
const { name, marks } = student;

// array methods pipeline
const avg = marks.reduce((sum, m) => sum + m, 0) / marks.length;
const passed = marks.filter(m => m >= 80);
const grades = marks.map(m => m >= 90 ? "A" : "B");

// spread — copy, don't mutate
const updated = { ...student, marks: [...marks, 95] };
Analogy

Think of map, filter, and reduce as an assembly line: map is a machine that reshapes every item passing through; filter is a gate that only lets qualifying items pass; reduce is a compactor that crushes the whole line into one final result.

Comparison

forEach

  • Just iterates, returns undefined
  • Used for side effects (logging, DOM updates)

map

  • Returns a brand-new array
  • Used to transform data, not for side effects

Common Misconception

array.sort() sorts alphabetically by default, even for numbers — [10,1,2].sort() gives [1,10,2]. Always pass a comparator: .sort((a,b) => a-b).

Key Takeaways

  • Destructuring extracts values from objects/arrays into named variables.
  • map transforms, filter selects, reduce aggregates — and none of them mutate the original array.
  • Spread (...) is the idiomatic way to copy/merge without mutation.
  • .sort() needs a comparator for correct numeric sorting.

04 Closures & the DOM Mastery

The capstone module: closures — the mechanism behind private state and callbacks — and the DOM, where JS actually meets the page the user sees.

Explanation

A closure is a function bundled together with references to its surrounding state. Even after the outer function has finished running, the inner function keeps access to those variables — this is how private counters, memoization, and module patterns work in JS.

The DOM (Document Object Model) is the browser's live tree representation of the page. document.querySelector finds elements; addEventListener reacts to user actions; changing element.textContent or .style updates what's rendered — all without reloading the page. 

// closure — private counter
function createBankAccount(balance) {
  return {
    deposit: (amt) => balance += amt,
    getBalance: () => balance   // balance is "closed over" — private!
  };
}
const acc = createBankAccount(1000);
acc.deposit(500);
console.log(acc.getBalance()); // 1500 — no direct access to "balance"

// DOM interaction
document.querySelector("#btn").addEventListener("click", () => {
  document.querySelector("#label").textContent = "Clicked!";
});
Analogy

A closure is like a backpack a function carries with it wherever it goes — packed with the variables from where it was born. Even if the function travels far from its birthplace, it can still reach into that backpack.

Comparison

Global variable

  • Accessible & mutable from anywhere
  • Easy to accidentally overwrite

Closure-based private state

  • Only accessible through exposed functions
  • Protected from outside interference

Common Misconception

"Closures copy the variable's value at creation time." False — they hold a live reference. This is why loops with var in old code famously all log the same final value, while let fixes it by creating a new binding per iteration.

Exercise

Key Takeaways

  • Closures let inner functions retain access to outer variables after the outer function returns.
  • Closures are the mechanism behind private state, memoization, and the module pattern.
  • The DOM is queried with querySelector and reacted to with addEventListener.
  • Closures capture live references, not snapshots — a classic source of loop bugs with var.

Summary Notes

JavaScript's core mental model: values live in variables (let/const), functions package behavior and create scopes, objects/arrays structure data with a rich set of non-mutating transformation methods, and closures let functions remember the environment they were created in — which is also how they eventually connect to and manipulate the live DOM.
