How this was built

System prompt design

The tutor's brain is one system prompt with four jobs: (1) stay scoped to CSE/programming concepts and gently redirect off-topic asks, (2) always produce a plain-language explanation before any formal definition, (3) always include exactly one vivid analogy per response, wrapped so the UI can render it in its own card, and (4) close by checking understanding with a small question rather than assuming the explanation landed. Difficulty level is injected as a variable so the same prompt scales from beginner to advanced without rewriting it.

UI decisions

  • Chalkboard-meets-notebook palette instead of the usual dark-mode-with-neon-accent: deep green-black board tones with a warm amber accent, because the brief is about a human tutor's patience, not a SaaS dashboard.
  • The analogy card is the signature element — every tutor reply that contains an analogy gets it visually separated into its own amber-bordered card, because the analogy is the actual "aha" moment and deserves to be found at a glance, not buried in prose.
  • Level rail sits above the chat because it changes how every future answer is phrased, so it needed to feel like a standing setting, not a one-off input.
  • Empty state offers real, working starter questions so a first-time user isn't staring at a blank box.

Engineering notes

  • Single HTML file, no build step, no external libraries. Fonts fall back gracefully if unavailable.
  • Calls api.anthropic.com/v1/messages directly via fetch with the full running conversation sent each turn (the API is stateless).
  • Analogy detection is done by asking the model to wrap its analogy in [[ANALOGY]]...[[/ANALOGY]] markers, which the client parses into the styled card — no regex guessing over free prose.
  • Handles empty state, in-flight loading (animated typing dots), and network/API errors (inline error bubble with a retry-friendly message) as first-class states, not afterthoughts.

Where this goes next

  • Memory: persist which concepts a student has asked about across sessions, so the tutor can say "last time you were stuck on recursion — this builds on that."
  • Tools: a code-execution tool so the tutor can generate and actually run a tiny snippet live to prove a concept (e.g. show recursion's call stack growing).
  • Multi-step workflows: an optional "quiz me" mode that chains three escalating questions and adapts the next one based on whether the last was answered correctly.
  • Multi-modal: auto-generate a simple inline diagram (SVG) alongside the analogy for spatial concepts like memory layout or network handshakes.
